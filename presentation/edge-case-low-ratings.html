🚨 Critical Edge Case: Low Ratings in Recommendations

What happens when poorly-rated recipes appear in high-visibility recommendation contexts?

The Problem

When we show community ratings, low-rated recipes (e.g., 2.5★) may appear in contexts where users expect only "recommended" or "curated" recipes:

Top 20 This Week
Recipe Image
Spicy Chicken Stir-Fry
★ 2.5 (47 ratings)

❌ Cognitive dissonance: "Top 20" but 2.5 stars?

For You
Recipe Image
Veggie Pasta Primavera
★ 2.8 (32 ratings)

❌ Trust erosion: "Why is HF recommending this?"

Risk: Users lose trust in HelloFresh curation, question recommendation quality, reduce overall meal selection confidence

1
Hide Ratings in Recommendation Contexts

Don't show community ratings in "Top 20", "For You", or preselected meals. Only show ratings in menu browse and detail pages.

Top 20 Card
Spicy Chicken
★ 2.5 (hidden)
Menu Browse
Spicy Chicken
★ 2.5 (47)

Pros

  • Eliminates cognitive dissonance
  • Protects brand trust
  • Simple to implement (CSS only)

Cons

  • Reduces rating visibility
  • Users may feel deceived later
  • Doesn't solve root cause
2
Rating-Weighted Algorithm

Update recommendation algorithms to factor in rating scores. Low-rated recipes (<3.5★) are automatically deprioritized.

Algorithm
High-Rated Recipe
★ 4.5 × 1.2
Algorithm
Low-Rated Recipe
★ 2.5 × 0.7

Pros

  • Improves recommendation quality
  • Aligns with user expectations
  • Incentivizes recipe improvements

Cons

  • Requires backend algorithm changes
  • May conflict with business goals
  • 3-4 weeks implementation time
3
Dynamic Threshold per Context

Show ratings BUT apply minimum thresholds: "Top 20" only shows if ≥4.0★, "For You" only if ≥3.5★, Menu browse always shows.

Pros

  • Context-aware solution
  • Protects high-visibility areas
  • Frontend-only (1-2 weeks)

Cons

  • Inconsistent UX
  • Users notice selective hiding
  • Doesn't address root cause
4
Transparent Labeling

Show ALL ratings but add context labels: "New recipe", "Recommended based on your preferences", with info tooltips explaining recommendation logic.

  • Full transparency
  • Educates users on algo
  • Consistent UX

Cons

  • May not prevent negative reaction
  • Requires careful copywriting
  • Users may ignore explanations
5
Hybrid: Threshold + Algorithm
✓ Recommended

Phased approach:
M1: Use dynamic thresholds (Solution 3) for immediate protection
M2: Add "New recipe" / "Limited ratings" labels
M3: Implement rating-weighted algorithm (Solution 2)

Why Hybrid?
Provides immediate brand protection (M1) while building sustainable solution (M3). M2 bridges the gap by adding transparency for edge cases. Allows iterative learning and adjustment based on real user behavior.
